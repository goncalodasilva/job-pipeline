# Code reviewer memory

Recurring issues and project-specific patterns, one line each. Keep this file short and current.

- Test maintenance (ADR-133): judge code and tests against the spec and approved ADRs. Correct justified test errors without asking, recording the requirement, reason, preserved coverage and verification. Older notes about test-edit approval describe the former policy; unclear or conflicting requirements still need the user's decision.
- Restore eligibility must be checked inside the write transaction that replaces data. A preflight empty-workspace read leaves a window for another connection's committed row to be silently deleted; pin this with a real second-connection write at transaction entry (M9.1 A).

- Partial export retries must retain the original rendering inputs across formats, including mutable details, photos and role headers. Semantic actions such as "mark Applied" need stable status keys rather than user-reorderable column positions (M6.10).

- Marker checks must use `item.get_closest_marker(name)`, not `name in item.keywords` (keywords include node names: dirs, param ids); pytester tests should place fixtures where dir names can't mask the bug.
- import-linter `forbidden` contracts check indirect chains by default; layered "X must not import Y" rules where X legitimately reaches Y via services need `allow_indirect_imports = true`, plus a positive self-test of the legal chain.
- Coverage/gate scripts: check they fail closed (e.g. report without branch data must not read as 100%), and that relative paths in coverage reports are relative to the cwd at report time, not the repo root.
- mypy only checks `app/` (files=["app"]): "conformance" tests in tests/ that pass a fake to a Protocol-typed helper prove nothing at runtime; require a mypy-checked check (e.g. pytest-run `mypy` over the test file, or typed assignments in app) instead.
- Protocol data members declared as plain attributes (`mode: Literal[...]`, `available: bool`) are settable and invariant: implementers with narrower types or `@property` fail conformance; prefer read-only `@property` members in interface protocols.
- AppError.detail is log-only and user_message is fixed: errors raised at start-up (config, before logging exists) need an explicit plan for who prints the setting name, or the user sees a generic message with no hint. Also check env/bootstrap paths: relative or `~` values depend on cwd.
- SQLite (isolation_level=None): verify `in_transaction` after `executescript` (script COMMIT/END/ROLLBACK silently autocommits later writes); a failed COMMIT leaves the tx open unless rolled back; one connection shared across threads (check_same_thread=False) needs a lock or per-thread connections.
- Migrations: fresh-vs-stepped equality replaying the same SQL files is near-tautological (needs a golden schema snapshot or .py data steps to bite); `IF NOT EXISTS` DDL the runner pre-empts never runs, so test it on a bare DB; non-STRICT `CHECK (n >= 1)` accepts text.
- asyncio shutdown: `suppress(CancelledError)` around `await worker` swallows the caller's own cancellation (verify with a cancelled stop()); lifespan `finally` with sequential cleanups skips later ones (db.close) if an earlier await raises.
- Request guards keyed on client-controlled headers (e.g. "no HX-Request = page load, token-free") let any route opt out; probe the middleware directly with a raw ASGI scope and prefer a server-side route allowlist.
- FastAPI 0.142 `include_router` adds a private `_IncludedRouter` (prefix/tags applied lazily), so `app.router.routes` isn't flat: route-walking guards (page matcher) miss included routes or mis-handle prefixes; match in dispatch order, first FULL match wins.
- Logging: `Handler.handle` doesn't guard `filter()`, so a filter calling `getMessage()` turns bad format args into exceptions at the call site; `uvicorn.run` with default `log_config` re-runs dictConfig and reinstalls handlers (propagate=False), undoing our setup unless `log_config=None`.
- htmx 2.0.x `historyRestoreAsHxRequest` defaults true: history-cache-miss restores send `HX-Request: true` without body `hx-headers`, so they hit the token check (403) and `render()` would return a fragment; check render/middleware/htmx-config handle `HX-History-Restore-Request`.
- CSS e2e tests reading getComputedStyle must target the element that declares the property (e.g. transition on `.sidebar a`, not `#sidebar`); prove they bite by deleting the rule via CSSOM in a scratch Playwright run.
- check_critical_coverage without `--milestone` reports a missing registry path as "not yet present" and passes (how the wrong `middleware.py` path went unnoticed); check registry paths against real files when modules move.
- When CI/verify flags or semantics change, grep docs/DECISIONS.md and PROGRESS ACs for the old command: ADRs restate usage (e.g. ADR-028 "used by CI") and go stale; changed gate semantics need an ADR note. Also check the change does not loosen the gate for the current milestone.
- Decorator stores (RedactingSecretStore over Chained): check extra inner methods (`source()`) stay reachable without bypassing the wrapper, and that constructor side effects (preload reads) can't hit the keychain at start-up when wired over the chain.
- Once-only operations (open_workspace, attach_log_folder): check that a failure midway doesn't leave a one-shot side effect done (log handler attached, files written) so every retry fails; probe with a failing first call, then a retry. Also: a retry after partial success (open ok, config write failed) may take a different "already open" branch with weaker rules (locate never rewrote config.toml).
- Start-up/routing decisions: check each outcome is actionable by the downstream route in that state (e.g. "guide at Welcome" while the workspace is already open makes step 1 hit WorkspaceAlreadyOpen), and that single-target outputs (one banner step) have an ADR-backed precedence when two conditions hold.
- pydantic `frozen=True` is shallow: dict/Mapping fields stay mutable and make the model unhashable; a shared spec default returned by load() then becomes module-level mutable state. Prefer tuples or MappingProxyType.
- Framework-shaped interfaces landed before their users (Step protocol, registries): check the binding (who maps id -> handler, who marks done), that bare KeyError/ValueError on user-reachable paths become AppErrors (else 500), and that `Mapping[str, str]` forms can carry multi-value fields.
- Cached-decision objects (OnboardingState.refresh): a defaulted kwarg (`provider_healthy=True`) silently resets state on every caller that omits it; store each input and use None-keeps. Publish shared state (app.state.workspace) only after the follow-up refresh succeeds.
- Shared contract suites written against a fake first: check each assertion against the real provider's fixtures/ADRs (e.g. `response.model == request.model` vs ADR-044 item 9 "store the model the provider reports"; fixture frames report a concrete id, not the alias).
- Module code importing jinja2/yaml etc. breaks the services contract (forbidden jinja2, indirect chains checked) as soon as a service imports it; probe with a scratch copy + `lint-imports` before the consuming task lands.
- Prompt/template safety checks: text rules checked on template source are satisfied by `{# comments #}`/dead branches (check rendered output); render wrappers catching a fixed exception list miss ZeroDivisionError/RecursionError; `x in frozenset` on YAML values raises TypeError for lists.
- jsonschema: `ValidationError.json_path`/`.path` are built from instance keys (model-chosen under additionalProperties/patternProperties), so "schema-only" correction notes leak output text; default "object"/"array" type checks are dict/list only (MappingProxyType/tuples fail).
- Nested async generators (claude_agent_sdk `query()` wraps `process_query` in `async for ... yield`): `aclose()` on the outer one does NOT close the inner (PEP 533); its cleanup (CLI kill) runs later in a GC-finalizer task. Fakes that pre-collect messages hide this; probe with real `query()` + a transport whose close() records the task.
- Composition-root types (ProviderHealth/ProviderChoice/Wiring in app/wiring.py) are unimportable by api/services/onboarding (layers contract); types later routes/services need belong in modules/domain. Defaults that read os.environ in create_app make in-process tests depend on the dev's shell.
- platformdirs: `user_config_dir == user_data_dir` on macOS and Windows (same folder), so "refuse the config folder" rules reject the default data folder; tests with separate cfg/data dirs and Linux-only e2e hide it. On Windows platformdirs uses ctypes known folders and ignores APPDATA/LOCALAPPDATA env (needs `WIN_PD_OVERRIDE_*`).
- Form error echo that merges submitted fields into the handler context by key (`if name in form`) lets a POST override non-input context (mode, demo_command, demo); whitelist the step's input names.
- Two-store writes (keychain set, then versioned settings save): a VersionConflict/save failure or a kind switch leaves an untracked keychain item with no UI path to remove it; probe with a failing save and two concurrent POSTs. Run `--cov=app --cov-branch` on new modules: decision branches (stuck-probe, conflict) often go untested.
- Save-then-await flows (connection test): reloading settings after the save instead of using what this request saved, and marking done/caching "verified" after a long await without re-checking the settings version, let a concurrent save get a replaced config marked verified. Also check in-memory "result" caches are cleared on every path that changes state (refused saves that still commit) and that a test asserts the clearing.
- Step forms that save by "load current version, save, retry once on VersionConflict" are last-write-wins, not optimistic concurrency (no version in the form); and their failure branches (save error, conflict retry, mark_done error) are routinely left untested: check with `--cov-branch`.
- Run-scoped flags cleared on an event (--setup ended by finishing Done): test every entry state that reaches the event (first-run with the flag, not only reopened); AC scope narrowed by the implementer ("every page" -> app pages) needs an ADR note and a test pinning it.
- "Never touches X" flags (`mark_done=False`) tested only from a state where X is already done (idempotent end state) prove nothing; require a recording callable or a not-yet-done start state.
- Focus helpers that add `tabindex="-1"` to the autofocus target must skip natively focusable controls (else a refocused button/input drops out of Tab order); e2e should Shift+Tab/Tab back to it.
- Retry helpers taking a `change(value)` closure (`_update`): aborting by raising inside it lands in the generic `except Exception` (logged as a save failure, generic "try again"); re-validation on the retry needs a service test with a settings double that conflicts once and switches state (kind) in between.
- Leak/absence scans ("X never appears"): unasserted request loops pass vacuously if a guard (403/500) stops the value early; require status asserts per probe, and prove bite with a scratch `-p` plugin on PYTHONPATH that injects a leak (e.g. logs the value in ChainedSecretStore.set).
- E2E restart/step-list helpers: asserts between `start_app` and its `try` leak the process; reusing tmp_path truncates the first run's stdout/stderr (opened "wb"); `to_contain_text("Done")` on a step `<li>` is vacuous for the step titled "Done" (assert the `.step-status` span).
- Lock-free wake-up primitives (ShutdownSignal: register-then-recheck, `future.done()` guard): `--cov-branch` shows the race branches partial and mutants survive; prove with a dict subclass whose `__setitem__` calls `set()` before inserting, and a `set(); waiter.cancel()` before the callback runs. Thread/signal tests do bite on `call_soon` vs `call_soon_threadsafe`.
- Subprocess smoke tests (RunningApp): to prove bite, put a `sitecustomize.py` that no-ops the hook on a scratch PYTHONPATH (isolated_env appends the caller's PYTHONPATH); fetch-reader JS can be probed with a Playwright init script replacing `window.fetch` with a chunked ReadableStream (route.fulfill delivers one chunk, so split-chunk parsing is otherwise untested).
- Long-lived per-tab streams (SSE via fetch) on HTTP/1.1 use one of Chrome's 6 connections per origin: the 7th tab's page loads hang; ADR/design notes for live-update spikes should say how that is handled (leader tab, close when hidden).
- pytester + `--import-mode=importlib`: an inner `tests/conftest.py` resolves to the outer `sys.modules["tests.conftest"]`, so "copied" conftest edits are dead (probe: copy with the hook removed still passes). Inner tests that fail before awaiting a coroutine leak "never awaited" unraisable warnings onto a later outer test (fails under `-W error`); close the coroutine.
- Resources passed into a helper that also creates its own (`lock=` reused by open_workspace_folder): check who releases a caller-supplied one; callee release (db.call_on_close) leaves the caller logging unlocked after a failed lifespan, and a reused app/lifespan gets an already-released handle and silently runs unlocked.
- Schema review: a time text column inside a UNIQUE key (budget_notices.cycle_start) dedupes only if every writer formats identically (+00:00 vs Z, microseconds); closed CHECK sets on growing lists (services) on non-STRICT tables need a table rebuild to extend.
- Repos landing after their migration: check queries use the indexes the migration comments promise (tasks list_recent by updated_at vs tasks_created_at), that the only insert path validates initial state (status/attempt), and that "not a state change" writes (heartbeat) have a test pinning version/updated_at unchanged.
- Post-commit publishers (TaskService.on_change) run on whichever thread committed: two threads can publish out of commit order, so consumers must refetch (or events carry version); "missing" folded into a refusal error (TaskNotRetryable) blocks the 404 a later route needs.
- Local-midnight cycle math: random Hypothesis instants almost never land on a DST-at-midnight day (Sao Paulo 2018-11-04 gap, Havana fall-back ambiguity); require pinned examples. Validators doing `value in frozenset` on settings/form values raise TypeError for lists.
- Limit services reading a settings blob: "invalid stored value -> default" silently fails open (no limit), and a later read-modify-write save drops the other entries; this branch is usually untested. Also check one error type isn't reused for a different refusal (tier cap -> "Monthly limit reached") and that `skip_*` bypass flags are tied to the one caller they're for.
- "Wait to the end, then re-raise the cancel" helpers (`settled`): the awaited result is discarded on cancel, so `ids.append(await settled(reserve))` loses the record id; probe each call site with a gated thread + cancel (reserve AND complete), not only a cancel during the provider call.
- Combined timeouts (`_earliest(call, run_timeout)`): a `min`->`max` mutant survives unless a test sets both with each one shorter; and "type timeout > provider run timeout" floors must add the bounded close (DISCONNECT_TIMEOUT 25 s), which runs after the deadline.
- Thread-hop tests (`publish` from a worker thread) that then await `to_thread`/`thread.join` wake the loop themselves, so a `call_soon` (not `_threadsafe`) mutant survives; require an otherwise idle loop or loop debug mode. Probe with a scratch `-p` plugin replacing the method. Async-generator stream cleanup (`finally: unsubscribe`) runs only at GC when the client leaves while the generator sits at a `yield` (blocked send).
- Fail-closed stored state (unreadable usage budgets) must be visible where the error message sends the user: a view built from `load_budgets()` drops the `unreadable` flag and shows "No limit" with no Remove button.
- Real-kill/restart subprocess tests: prove bite with a scratch copy of the repo (rsync without .venv/.git, run the original `.venv/bin/python -m pytest` from the copy; `PROJECT_ROOT` follows the copy) and mutate app SQL/services there. A sentinel "no automatic retry" test only covers claim-order and recovery-time retries (caught by the immediate status read, not by the sentinel); a timer/watchdog retry after ~1 s stays invisible, so say so instead of calling it a "wait".
- Guide steps that save versioned data and then mark the step done (web search budget): if the second write fails, the 422 echoes the pre-save version, so "Try again" answers 409 "not saved" though it was saved; probe by making the handler's `_mark_done` raise once, then re-POST the echoed form. New-step tasks also tend to leave the user's decision and approved test changes unrecorded in DECISIONS, and tests derived from the registry (`ALL_M1_DONE`, `finished_guide`) change meaning silently.
- [CI, Windows, start-up and vendor quirks](ci-windows-vendor-quirks.md) — gitleaks scope, CRLF hashes, CI concurrency, uvicorn exit/signals, excepthook, keyring 25, wheel tags, Windows paths.
- [Task runner race probes](task-runner-races.md) — stop/cancel during finish, lost notices before registration, hand-off ordering spies, commit-then-act loops, attempt-keyed writes.
- [htmx and live-UI probes](htmx-live-ui-probes.md) — event-refreshed fragments, 409 forms (409 plain text swapped into outerHTML regions), dialog guards, Web Locks, seen-state.
- [Docs task checks](docs-task-checks.md) — wrong-but-plausible facts, skills copied from one example, UI label names, acceptance draft scope.
- [Import pipeline checks](import-pipeline-checks.md) — kept uploads with no handle, digit-run number check false negatives, Retry skipping the budget gate, remove order.
- Child-process helpers (extract runner, spawn): child code is invisible to coverage and its unhandled errors print tracebacks to the app stderr; probe a result over the pipe cap (9 MB text -> "damaged" + BrokenPipe traceback), a failing `start()` (raw error, pipe end leaked), and time start-up with `app.cli` as `__main__` (~0.6 s counted in the timeout). Upload readers: test the exact cap and cap+1 (the envelope allowance hides the second size check) and spy `SpooledTemporaryFile.rollover` for "memory only" claims.
- Append-only/immutability triggers (BEFORE UPDATE/DELETE): `INSERT OR REPLACE` deletes the old row without firing delete triggers (recursive_triggers is off), so it rewrites "immutable" rows and can leave stale FTS rowids; need a BEFORE INSERT "id exists" guard. Mutation-test migrations in a scratch repo copy by dropping each trigger/composite FK (run the schema test file with `-k "not hashes" -o addopts=`): guards the plan didn't name (events, number, cross-fact FKs) are usually untested.
- Text compared for "no change" (next_version) or diffed: browsers post textarea newlines as CRLF, so check newline normalization before compare and store.
- Append-only versions with per-version provenance (provider, needs_check): a label read from the current version is dropped by a one-character edit or a merge that takes the AI wording verbatim; probe both. Undo guards that compare version ids ("merge version is still current") break last-in-first-out undo of two merges, because each undo appends a version; probe merge A, merge B, undo B, undo A.
- The working tree can change mid-review (implementer fixing a known issue in parallel): re-run `git status` and re-read touched files before reporting; say which state was reviewed.
- Validation added to a shared save path (`_checked_input`: end-before-start) also runs for narrower forms (inline reword-and-confirm) that have no field for it: the 422 lands on the wrong field; probe each caller with stored data that breaks the new rule. Answers picked by sniffing `HX-Trigger` ids (Library "Restore draft") leave the 409/422 branches answering the other screen's block and reload link.
- Editor/merge screens (M3.6): 409 that re-renders "typing kept" loses it when the fact became uneditable (discarded); "can't be undone" copy must cover "a later merge still stands"; refused saves tested only before the transaction need an `assert_atomic` run with the new in-transaction writes (NewRole).

- Shared coding-tool hooks must distinguish the checkout root from the event/tool working directory; relative patch paths, rename destinations and post-edit checks use the operation directory, while protection compares against the checkout root. Test both a nested session cwd and explicit exec workdir.
- Shell policy path scanning must inspect equality-form option/assignment values and adjacent control punctuation (`;`, `|`, redirects); compare canonical and space-separated native payloads with synthetic data paths.
- Honesty checks on AI suggestions (refine, M3.8): probe with a pure `new_claims` script: number words ("fourteen", "doubled"), single capitalised names after `;`/`:`/newline (treated as sentence starts), and names supported only by a "generalize" context fact pass unflagged. Accept paths using a stored source snapshot must recheck privacy changes since (never-use context) and whether the fact moved on since the suggestion (lost manual edit). Number-word readers: probe "-fold"/"dozen"/plural scales ("thousands")/fractions (unread) and pronoun "one" ("no one", "one of": false positives). "Waiting for an answer" guards must check the last turn asked something, not only that it is unanswered.
- Suggestions pinned to a source version (refine snapshot `fact_version_id`): after the user edits the source, Accept answers the generic VersionConflict "Reload", and reload shows the same stale suggestion (409 loop); the panel should say so up front and offer Discard/refine again. Check the same for a conversation left open when the fact turns never-use/archived (panel hides the blocked reason).
- HTTP fetch tests (M4.1): `httpx.Response(content=...)` in a MockTransport handler reads and gzip-decodes in `__init__`, so "bomb"/"stops reading" tests built with `content=` never exercise streaming decode (use `stream=` with compressed chunks); httpx decoders inflate one 64 KiB chunk to ~64 MB (no max_length). An "overall deadline" test with one stalled step doesn't kill a per-hop-timeout mutant: use several hops each under the limit.
- HTML text extractors keeping an open-element stack for dropped/hidden parts must apply implied end tags: an unclosed `<li style="display:none">` or `<p hidden>` (valid HTML) swallows the rest of the list/page. "Prefer JSON-LD description" paths drop company/location/salary unless they read `hiringOrganization` etc.
- Seeds and CHECKed key lists in migrations (controlled values, M4.2): grep the existing domain Literals and settings for the same keys before approving (seed `onsite` vs `WorkMode` `on_site`); the task text itself can carry the wrong spelling, and a committed seed needs a data migration to fix.
- Derived-state domains (due snooze reads as New): check every transition uses the same effective state the list shows, not the stored one; otherwise an action on a card the queue shows as New is refused until a background "mark seen" lands.
- Mutation probes on "ORDER BY created_at DESC, rowid DESC LIMIT 1" tie-breaks are usually equivalent mutants when an index on (key, created_at) exists (index ties are rowid-ordered); don't demand a test that can't bite.
- Intake URL validators must normalize accepted variants before storage: uppercase schemes pass a case-insensitive check but fail lowercase SQL GLOB constraints. Duplicate split regressions must assert the destination of later pasted/new-link sources, not just root counts. Compare the strongest snapshot and keep ambiguous matches across dismissed groups separate.
- A timeout around `to_thread` cancels only the await, leaving hostile parsing active. Bound parser depth and total work inside the worker; a character cap alone still permits quadratic stack scans. Refuse the whole page, including JSON-LD description parsing, with no partial snapshot.
- Passing serious/critical axe scans do not prove the project's 24px target minimum. Use shared form/button styles and assert browser dimensions on phone layouts.
- Summary source checks must bind units to quantities: a salary amount cannot borrow a currency from another allowance, and a number near “years” may describe company age or benefits. Inspect actual string leaves for reflected instructions; JSON serialization turns whitespace into escapes and can hide multiline matches.
- Budget flows can chain a tier-cap offer and a warning. Carry the accepted Fast override in the warning's hidden fields, and serialize explicit task tier values rather than treating every nonempty tier as Fast.
- A delayed initiating POST can finish its task before the response installs ownership of completion announcements. Hold the real response until the indicator reports completion, then assert one notice. Measure save/start acknowledgment dwell from its delivery, not request start; a virtual clock exposes the slow-response case. Derive completion words from the actual attempt status, not the presence of an older result.
- Automatic handoffs need source eligibility checked atomically with enqueue. Two callbacks can both see an unassessed source; active dedupe no longer protects the second if the first paid task finishes while the second waits at the gate. Hold the second gate until the first task succeeds, then assert one request.
- Normalize accepted currency aliases consistently across extraction and later comparisons. A validator accepting “€” while a preference comparison accepts only “EUR” silently loses a mechanical conflict flag.
- Normalize evidence before checking nonemptiness. An invisible-only quote can pass `strip()`, normalize to an empty substring and match every source; store the cleaned visible evidence. Caption reference-only injection fixtures narrowly: valid ids and source quote presence do not establish semantic truth.
- Pagination inputs need a bound on the derived SQLite OFFSET, not only a positive-integer check; Python integers can exceed SQLite's signed-64 range. EXPLAIN assertions must identify the intended jobs/FTS access, rather than accepting an index used only by a joined lookup table.
- Forms with several named submit buttons (reason chips, "Tomorrow" + date field): Enter in a text/date input submits with the FIRST button's name/value (duplicate `reason`, or `choice=tomorrow` beating the picked date); probe Enter in each input. Post-swap pages: removing the last row on page N>1 renders the empty state (no pager) and drops focus to body; the swap target's focus fallback needs a heading when no card remains.
- Client-side "hold an action until the seen/version answer" (shortcuts.js, M4.7): check the held form is not dropped silently when a self-refresh swaps the card, the timeout/failed-answer release has its own e2e (route.abort or clock), and guards on self-refresh cover every refresher (#inbox as well as the card), not just the one the comment names.
- Form with several submit buttons: implicit Enter submit picks the first button, and duplicate field names are rejected (400); give each form one default submit and test Enter in every text field.
- A sibling action that advances an untouched editor's version must send its exact committed version, never a later refetch version. Gate an edit between commit and view, then prove the old full editor still gets 409.
- Check refresh safety again before swapping: focus or a menu can become active while a GET is in flight. Identify GETs from requestConfig.verb; beforeSwap's elt may be the swap target even for an explicit POST. Preserve refused-save drafts as well as freshly typed values, since echoed inputs have new defaultValue values.
- GET filter forms using `hx-get=<fragment route>` with `hx-push-url="true"` push the fragment URL (reload/Back = 403 Forbidden); give an explicit page push URL and reload in the e2e. Group-by on a paginated list: headings carry whole-set counts while the section lists only the page's rows; probe with more than 50 jobs.
- Draft caches need cleanup both when a restored form becomes clean and when a delayed successful save settles after its originating drawer is removed; process success before any DOM-presence guard.
- Detail pages whose edit POST swaps only the form block (companies, M4.10): every other displayed copy of an edited field (website link, `<title>`, heading) stays stale unless sent out of band; the e2e should edit each displayed field and assert the visible copy changes without reload. Also run `--cov-branch` on new domain validators: the "no letters or numbers" name error, the places cap and the no-op edit were untested.
- Leak-scan "stored only where it belongs" controls (M4.11): asserting only `"tasks" not in tables` leaves usage_records, budget_notices and settings unscanned; assert the stored tables are a subset of the expected ones. "Distinct" fixture texts built from one template can sit just under a similarity merge threshold (0.792 vs 0.80 in M4.11): compute the pairwise score before trusting "no accidental duplicate". When a docs task extends an AC (AC-M1.4 to job text), check the spec section that states the rule (2.10 Logging) was edited, not only the M-notes in section 5.
- Calendar parsers can accept invalid serialized dates: inspect raw VEVENT fields as well as round trips, including UTC aliases and both occurrences of an autumn hour. Scope DTSTART assertions to VEVENT so a VTIMEZONE DTSTART cannot satisfy them. Shared vendor READMEs may have consumers that read the first Version entry; preserve existing sections when adding libraries.
- User preference (2026-10-20): when a design decision requires approval, present established solution options, their implications and a recommendation together before asking the user to choose.
- SQLite conflict handling can bypass DELETE triggers through UPDATE OR REPLACE and implicit rowid/oid/_rowid_ collisions as well as INSERT OR REPLACE. Probe these paths for immutable history and protected parent deletion; stable explicit keys plus WITHOUT ROWID on new protected tables remove hidden-key bypasses.
- All-day dates and entered wall times have different gap semantics: a valid date may start at 01:00. Resolve synthetic date boundaries to the first real instant, keep explicit timed gaps refused, and test both the start and exclusive-end boundary plus a wholly skipped date.
- "Is one transaction" tests that inject a failing IdFactory prove nothing when the service makes its ids before the first write (M5.3 apply/move); fail after the first write (second insert, trigger) and compare a full snapshot. Swap-based reorder of a global `position` across phases, read by a board ordered by position alone, moves a built-in column (Preparing) to the far end; order by (phase, position) or renumber per phase. Query tests whose fixtures always have every optional value (company, applied_at, upcoming event) leave NULL-ordering arms and "past event hidden" filters unexercised; and `page` fed into OFFSET needs a clamp (OverflowError beyond 2^63/page size).
- Board/Sortable (M5.4): Sortable 1.15 pushes every list into a module-global array and only `destroy()` removes it, so re-creating instances after each htmx swap without destroying the old ones (`htmx:beforeCleanupElement`/`beforeSwap`) leaks the detached lists and their cards; check `Sortable.get(old)` after a swap. Disclosure menus that close on `focusout` break mouse selection in Safari/macOS Firefox (buttons take no focus on click, `relatedTarget` is null, the menu hides on mousedown); Chromium-only e2e that picks every item by keyboard hides it. State read from `HX-Current-URL` (Closed open) needs a test that sends it; an e2e that does `if aria-expanded == "false": press` accepts both outcomes and kills no mutant.
- Derived-set fixes (M5 "To apply = triage_state to_apply AND application still Preparing"): grep every consumer of the raw column (view page/total/groups share `_where`; companies listing; card/drawer flags) and probe the round trip Preparing -> other -> Preparing: history makes Undo refuse (version > 1), yet the card shows "Back to queue" again, so a test asserting that button codifies a refused action.
