Moved from MEMORY.md on 2026-10-11 to keep the index short. Verify names against the code before citing them. Related: [[task-runner-races]].

- Conditionally shown page sections (Testing tools, gated on saved provider): an htmx POST that swaps only a sibling section (#providers) leaves the gated one stale (shown or missing until reload); check for an OOB swap or HX-Refresh, and that the stale form's 404 has a sensible client message. Also run `--cov-branch` for "no longer offered at run time" handler branches.
- Web Locks leader callbacks (`lead()`: connect, then return the hold promise): a synchronous stop inside the callback (no token) runs the release before the resolver exists, so a stopped tab holds the lock for ever and followers never connect; probe with a routed page whose hx-headers lacks the token plus a second tab. "No retry" e2e asserts need a paused clock run past the backoff, or they pass before the 1 s timer.
- Event-refreshed fragments (tasks panel/items): a POST answer swapped with no published change (retry -> active duplicate, 409) is never corrected by the event refetch (duplicate ids, stale list); swapped buttons need stable ids (htmx restores focus by id only) plus `data-autofocus`/announce; htmx `responseHandling` edits need a config test, an ADR-041 note, and a check that 404 fragments (unswapped) aren't the only message.
- Version-checked forms: a 409 answer re-rendered from a fresh view carries the NEW hidden version next to the typed values, so a second Save overwrites without a reload (probe: stale POST, read the answer's version, POST again); keep the submitted version or drop Save. Out-of-band version refreshes for sibling forms need their own assert (integration: the `hx-swap-oob` inputs; e2e: save two forms in one tab without reloading).
- Client-side "disabled" guards (aria-disabled + capture-phase click/submit block): an e2e that asserts only "nothing started" passes with the guard deleted because the server refuses with the same fragment (require `posts == []`); and a blocked state rendered once goes stale when a sibling section lifts it (budget removed on the same page), where the guard then stops the request that would correct it. Confirmation tokens posted back by a dialog should name the service they were shown for, not only threshold + cycle.
- htmx resolves `hx-target` when the request is sent: two elements refetching the same outerHTML target (panel self-refresh + a wrapper's timer) make the second answer swap into a detached node (newer data dropped); prefer one requester. Client "skip identical swap" + "restore focus by id" mask each other in tests (need a node-identity assert and a real swap), and "first answer is a silent baseline" tests must wait for that first answer before acting.
- Read-only panels over service state (usage panel): "optional element" test loops (`for bar in bars`) leave the element's own attributes unpinned (a wrong `<progress value>` survives); a "the rest" bucket (`information_only` = snapshots not compared) needs an exclusion assert (mutant: bucket = all) and a freshness rule (latest-row-per-key snapshots are shown for ever with no "as of"); panels refreshed only by their own form's event go stale when another section of the same page changes the data (practice task).
- "Seen" stamps that gate a refetch (Fact bank `drafts_seen`, M3.5): check the view reads the stamp's source BEFORE the data it describes (data first, stamp second = a change in between is marked seen and never fetched); check the server side of the stamp has an integration test (header fired / not fired), not only an e2e happy path; group-level swaps (batch answer, region refetch) remove per-item one-shot controls such as Undo. Client rules that swap error statuses by content type (`data-shows-refusals`, 400/413 + text/html) also swap the empty `HTMLResponse("", 413)` backstops and delete the target.
- Browser-remembered "seen" state (needs-attention keys in localStorage): "X never counts" e2e asserts are vacuous when X happens while the panel is open (all shown keys are marked seen), so pin the server's key list per status in an integration test; the `storage`-event (second tab) path and local-zone rendering (mutant: drop `.astimezone(tz)`) go untested; token-shape checks on log args are bypassed by f-string messages. Mode gates keyed on a CLI flag (`--demo` => fakes): check the flag combined with an explicit data folder (`--data-dir`/env win over the demo folder).
- base.html `responseHandling` swaps 409 (and 422) app-wide: a `PlainTextResponse(..., 409)` from a route whose form targets a region with `outerHTML` replaces the region with bare text, so later `hx-target="#region"` buttons hit nothing until reload (M3.7 duplicates dismiss). Check every new 409 answers the target's fragment, and that stale on-demand regions (not refreshed by sibling actions) can reach it.
