### Inbox acceptance fix

The reported Add job failure was a successful intake followed by a queue refresh returning
500 (`JobNotFound`). A concurrent summary merge could invalidate the selected card between
separate list and card reads. Queue, grouped counts and selected card now use one SQLite
snapshot. Automatic seen/card requests that arrive after a merge recover by refreshing the
queue; recovery preserves open dialogs and typing, and refuses delayed responses after a
new card selection. Direct requests for missing jobs retain their fixed 404.

Tests failed before the fixes. All 19 focused cases passed: three integration snapshot
variants and 16 desktop/phone browser cases, including keyboard, focus, axe, held editor
responses, a newer card selection and a user-action 404 negative control. Evidence:
`tests/integration/test_inbox_snapshot.py`, `tests/e2e/test_inbox_snapshot.py`, and
`/private/tmp/jobpipeline-inbox-final2-focused.log`. The full run includes all these tests.
User retesting remains on the M6 checklist (TD-254); an older inbox error report is not
assumed to have the same cause.
