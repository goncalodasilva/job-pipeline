# Code reviewer memory

Recurring issues and project-specific patterns, one line each. Keep this file short and current.

- Marker checks must use `item.get_closest_marker(name)`, not `name in item.keywords` (keywords include node names: dirs, param ids); pytester tests should place fixtures where dir names can't mask the bug.
- import-linter `forbidden` contracts check indirect chains by default; layered "X must not import Y" rules where X legitimately reaches Y via services need `allow_indirect_imports = true`, plus a positive self-test of the legal chain.
- gitleaks pre-commit hook entry is `gitleaks git --pre-commit --staged`; `pre-commit run --all-files` does not widen it (no-op on a clean checkout). CI/history scans need a separate `gitleaks git` (fetch-depth 0) or a manual-stage hook with overridden entry.
- Vendored files checked by byte hash (axe, htmx) need `.gitattributes` `-text` (or LF-normalised hashing): Windows CI checkout with autocrlf rewrites LF to CRLF and breaks the hash test.
- CI workflows: `concurrency` keyed only on workflow+ref with `cancel-in-progress: true` lets a push cancel dispatch/schedule evidence runs on the same ref; workflow_dispatch and schedule only work once the file is on the default branch (main), so cross-OS evidence before merge needs a PR to main.
- Coverage/gate scripts: check they fail closed (e.g. report without branch data must not read as 100%), and that relative paths in coverage reports are relative to the cwd at report time, not the repo root.
- mypy only checks `app/` (files=["app"]): "conformance" tests in tests/ that pass a fake to a Protocol-typed helper prove nothing at runtime; require a mypy-checked check (e.g. pytest-run `mypy` over the test file, or typed assignments in app) instead.
- Protocol data members declared as plain attributes (`mode: Literal[...]`, `available: bool`) are settable and invariant: implementers with narrower types or `@property` fail conformance; prefer read-only `@property` members in interface protocols.
- AppError.detail is log-only and user_message is fixed: errors raised at start-up (config, before logging exists) need an explicit plan for who prints the setting name, or the user sees a generic message with no hint. Also check env/bootstrap paths: relative or `~` values depend on cwd.
- SQLite (isolation_level=None): verify `in_transaction` after `executescript` (script COMMIT/END/ROLLBACK silently autocommits later writes); a failed COMMIT leaves the tx open unless rolled back; one connection shared across threads (check_same_thread=False) needs a lock or per-thread connections.
- Migrations: fresh-vs-stepped equality replaying the same SQL files is near-tautological (needs a golden schema snapshot or .py data steps to bite); `IF NOT EXISTS` DDL the runner pre-empts never runs, so test it on a bare DB; non-STRICT `CHECK (n >= 1)` accepts text.
- asyncio shutdown: `suppress(CancelledError)` around `await worker` swallows the caller's own cancellation (verify with a cancelled stop()); lifespan `finally` with sequential cleanups skips later ones (db.close) if an earlier await raises.
- Request guards keyed on client-controlled headers (e.g. "no HX-Request = page load, token-free") let any route opt out; probe the middleware directly with a raw ASGI scope and prefer a server-side route allowlist.
- uvicorn 0.54 `Server.run` raises SystemExit(3) on lifespan or bind failure (never returns with started=False); lifespan tracebacks arrive as message text (starlette format_exc), not exc_info. Fakes of `serve` must model this; prefer handing uvicorn a pre-bound socket.
- `sys.excepthook` installed and restored in a `finally` around the protected code never fires for main-thread errors (restored before the interpreter calls it); catch explicitly instead.
- uvicorn re-raises captured signals after shutdown (`signal.raise_signal`): SIGINT -> KeyboardInterrupt, but Windows SIGBREAK has no Python handler, so the CRT default ends the process with exit 3 unless the app installs one.
- FastAPI 0.142 `include_router` adds a private `_IncludedRouter` (prefix/tags applied lazily), so `app.router.routes` isn't flat: route-walking guards (page matcher) miss included routes or mis-handle prefixes; match in dispatch order, first FULL match wins.
- Logging: `Handler.handle` doesn't guard `filter()`, so a filter calling `getMessage()` turns bad format args into exceptions at the call site; `uvicorn.run` with default `log_config` re-runs dictConfig and reinstalls handlers (propagate=False), undoing our setup unless `log_config=None`.
- htmx 2.0.x `historyRestoreAsHxRequest` defaults true: history-cache-miss restores send `HX-Request: true` without body `hx-headers`, so they hit the token check (403) and `render()` would return a fragment; check render/middleware/htmx-config handle `HX-History-Restore-Request`.
- CSS e2e tests reading getComputedStyle must target the element that declares the property (e.g. transition on `.sidebar a`, not `#sidebar`); prove they bite by deleting the rule via CSSOM in a scratch Playwright run.
- check_critical_coverage without `--milestone` reports a missing registry path as "not yet present" and passes (how the wrong `middleware.py` path went unnoticed); check registry paths against real files when modules move.
- When CI/verify flags or semantics change, grep docs/DECISIONS.md and PROGRESS ACs for the old command: ADRs restate usage (e.g. ADR-028 "used by CI") and go stale; changed gate semantics need an ADR note. Also check the change does not loosen the gate for the current milestone.
- New deps: check uv.lock wheel tags cover all three CI OSes (claude-agent-sdk 0.2.163 has no Windows wheel, sdist has no bundled CLI); env passed to vendor subprocesses that merge over os.environ must blank every credential-routing variable, not just the key.
- keyring 25: macOS `delete_password` wraps every error (denied, auth) in PasswordDeleteError, chainer delete returns None silently; `get_keyring()` raises on a bad PYTHON_KEYRING_BACKEND. Guard tests that name an autouse fixture don't prove it is autouse.
- Decorator stores (RedactingSecretStore over Chained): check extra inner methods (`source()`) stay reachable without bypassing the wrapper, and that constructor side effects (preload reads) can't hit the keychain at start-up when wired over the chain.
- Hypothesis path strategies: on Windows `base.joinpath("a:b")` / `"D:"` yields a drive-relative (non-absolute) path; random text segments containing `X:` make "absolute path" round-trip tests flaky on Windows CI only. Filter `:` or build with PurePosixPath.
- Once-only operations (open_workspace, attach_log_folder): check that a failure midway doesn't leave a one-shot side effect done (log handler attached, files written) so every retry fails; probe with a failing first call, then a retry. Also: a retry after partial success (open ok, config write failed) may take a different "already open" branch with weaker rules (locate never rewrote config.toml).
- Start-up/routing decisions: check each outcome is actionable by the downstream route in that state (e.g. "guide at Welcome" while the workspace is already open makes step 1 hit WorkspaceAlreadyOpen), and that single-target outputs (one banner step) have an ADR-backed precedence when two conditions hold.
- pydantic `frozen=True` is shallow: dict/Mapping fields stay mutable and make the model unhashable; a shared spec default returned by load() then becomes module-level mutable state. Prefer tuples or MappingProxyType.
- Framework-shaped interfaces landed before their users (Step protocol, registries): check the binding (who maps id -> handler, who marks done), that bare KeyError/ValueError on user-reachable paths become AppErrors (else 500), and that `Mapping[str, str]` forms can carry multi-value fields.
- Cached-decision objects (OnboardingState.refresh): a defaulted kwarg (`provider_healthy=True`) silently resets state on every caller that omits it; store each input and use None-keeps. Publish shared state (app.state.workspace) only after the follow-up refresh succeeds.
- Shared contract suites written against a fake first: check each assertion against the real provider's fixtures/ADRs (e.g. `response.model == request.model` vs ADR-044 item 9 "store the model the provider reports"; fixture frames report a concrete id, not the alias).
- Module code importing jinja2/yaml etc. breaks the services contract (forbidden jinja2, indirect chains checked) as soon as a service imports it; probe with a scratch copy + `lint-imports` before the consuming task lands.
- Prompt/template safety checks: text rules checked on template source are satisfied by `{# comments #}`/dead branches (check rendered output); render wrappers catching a fixed exception list miss ZeroDivisionError/RecursionError; `x in frozenset` on YAML values raises TypeError for lists.
- jsonschema: `ValidationError.json_path`/`.path` are built from instance keys (model-chosen under additionalProperties/patternProperties), so "schema-only" correction notes leak output text; default "object"/"array" type checks are dict/list only (MappingProxyType/tuples fail).
- Nested async generators (claude_agent_sdk `query()` wraps `process_query` in `async for ... yield`): `aclose()` on the outer one does NOT close the inner (PEP 533); its cleanup (CLI kill) runs later in a GC-finalizer task. Fakes that pre-collect messages hide this; probe with real `query()` + a transport whose close() records the task.
- Composition-root types (ProviderHealth/ProviderChoice/Wiring in app/wiring.py) are unimportable by api/services/onboarding (layers contract); types later routes/services need belong in modules/domain. Defaults that read os.environ in create_app make in-process tests depend on the dev's shell.
- platformdirs: `user_config_dir == user_data_dir` on macOS and Windows (same folder), so "refuse the config folder" rules reject the default data folder; tests with separate cfg/data dirs and Linux-only e2e hide it. On Windows platformdirs uses ctypes known folders and ignores APPDATA/LOCALAPPDATA env (needs `WIN_PD_OVERRIDE_*`).
- Form error echo that merges submitted fields into the handler context by key (`if name in form`) lets a POST override non-input context (mode, demo_command, demo); whitelist the step's input names.
- Two-store writes (keychain set, then versioned settings save): a VersionConflict/save failure or a kind switch leaves an untracked keychain item with no UI path to remove it; probe with a failing save and two concurrent POSTs. Run `--cov=app --cov-branch` on new modules: decision branches (stuck-probe, conflict) often go untested.
- Save-then-await flows (connection test): reloading settings after the save instead of using what this request saved, and marking done/caching "verified" after a long await without re-checking the settings version, let a concurrent save get a replaced config marked verified. Also check in-memory "result" caches are cleared on every path that changes state (refused saves that still commit) and that a test asserts the clearing.
- Step forms that save by "load current version, save, retry once on VersionConflict" are last-write-wins, not optimistic concurrency (no version in the form); and their failure branches (save error, conflict retry, mark_done error) are routinely left untested: check with `--cov-branch`.
- Run-scoped flags cleared on an event (--setup ended by finishing Done): test every entry state that reaches the event (first-run with the flag, not only reopened); AC scope narrowed by the implementer ("every page" -> app pages) needs an ADR note and a test pinning it.
- "Never touches X" flags (`mark_done=False`) tested only from a state where X is already done (idempotent end state) prove nothing; require a recording callable or a not-yet-done start state.
- Focus helpers that add `tabindex="-1"` to the autofocus target must skip natively focusable controls (else a refocused button/input drops out of Tab order); e2e should Shift+Tab/Tab back to it.
- Retry helpers taking a `change(value)` closure (`_update`): aborting by raising inside it lands in the generic `except Exception` (logged as a save failure, generic "try again"); re-validation on the retry needs a service test with a settings double that conflicts once and switches state (kind) in between.
- Leak/absence scans ("X never appears"): unasserted request loops pass vacuously if a guard (403/500) stops the value early; require status asserts per probe, and prove bite with a scratch `-p` plugin on PYTHONPATH that injects a leak (e.g. logs the value in ChainedSecretStore.set).
- E2E restart/step-list helpers: asserts between `start_app` and its `try` leak the process; reusing tmp_path truncates the first run's stdout/stderr (opened "wb"); `to_contain_text("Done")` on a step `<li>` is vacuous for the step titled "Done" (assert the `.step-status` span).
- Lock-free wake-up primitives (ShutdownSignal: register-then-recheck, `future.done()` guard): `--cov-branch` shows the race branches partial and mutants survive; prove with a dict subclass whose `__setitem__` calls `set()` before inserting, and a `set(); waiter.cancel()` before the callback runs. Thread/signal tests do bite on `call_soon` vs `call_soon_threadsafe`.
- Subprocess smoke tests (RunningApp): to prove bite, put a `sitecustomize.py` that no-ops the hook on a scratch PYTHONPATH (isolated_env appends the caller's PYTHONPATH); fetch-reader JS can be probed with a Playwright init script replacing `window.fetch` with a chunked ReadableStream (route.fulfill delivers one chunk, so split-chunk parsing is otherwise untested).
- Long-lived per-tab streams (SSE via fetch) on HTTP/1.1 use one of Chrome's 6 connections per origin: the 7th tab's page loads hang; ADR/design notes for live-update spikes should say how that is handled (leader tab, close when hidden).
- pytester + `--import-mode=importlib`: an inner `tests/conftest.py` resolves to the outer `sys.modules["tests.conftest"]`, so "copied" conftest edits are dead (probe: copy with the hook removed still passes). Inner tests that fail before awaiting a coroutine leak "never awaited" unraisable warnings onto a later outer test (fails under `-W error`); close the coroutine.
- Docs tasks (README/spec layout/env tables) routinely state plausible but wrong facts (file locations, CI scope per OS, where a setting is edited, env precedence, demo contents): grep each claim against code/workflows; flag credential placeholders inline in shell commands (history) and docs that contradict each other on that.
- Resources passed into a helper that also creates its own (`lock=` reused by open_workspace_folder): check who releases a caller-supplied one; callee release (db.call_on_close) leaves the caller logging unlocked after a failed lifespan, and a reused app/lifespan gets an already-released handle and silently runs unlocked.
- Schema review: a time text column inside a UNIQUE key (budget_notices.cycle_start) dedupes only if every writer formats identically (+00:00 vs Z, microseconds); closed CHECK sets on growing lists (services) on non-STRICT tables need a table rebuild to extend.
- Repos landing after their migration: check queries use the indexes the migration comments promise (tasks list_recent by updated_at vs tasks_created_at), that the only insert path validates initial state (status/attempt), and that "not a state change" writes (heartbeat) have a test pinning version/updated_at unchanged.
- Post-commit publishers (TaskService.on_change) run on whichever thread committed: two threads can publish out of commit order, so consumers must refetch (or events carry version); "missing" folded into a refusal error (TaskNotRetryable) blocks the 404 a later route needs.
- Async task runners: probe (1) a handler that returns while stop() runs (cancel lands in the to_thread finish, conditional INTERRUPTED wins, result lost), (2) a handler raising CancelledError itself (done-callback drops it, row stuck running), (3) one failed claim (queue waits for an unrelated notify).
- "X before first claim" ordering tests that spy on claim_next only bite by race (recovery moved after runner.attach: step1 caught 2/3, lifespan 0/3); require a spy at the hand-off (runner.attach/_attach_tasks) asserting committed state there.
- Multi-step "commit then act" loops (watchdog: interrupt_stale per type, then cancel handlers): a raise on a later step skips the action for rows already committed, and they never come back (no longer running), so a hung handler keeps its slot; act per step. Also `col < ?` on a nullable column never matches NULL rows. Check "floor" constants actually bound what they claim (CONNECTION_TIMEOUT is not a run timeout).
- Commit-in-worker-thread awaited via bare `to_thread` (ctx.complete): a cancel at the await abandons a still-running commit; if the handler swallows it, the runner's own finish can race the commit (stop() commits nothing first). Shield and await the thread's result before re-raising.
- Event-driven cancel/notify keyed on an in-memory registry (runner `_handlers`): a notice published between the claim commit and registration (`_spawn`) finds no entry and is lost; probe by wrapping claim_next to request_cancel in-thread. Same-row retries: finishes/heartbeats keyed on id only can land on attempt N+1 (match attempt).
- Local-midnight cycle math: random Hypothesis instants almost never land on a DST-at-midnight day (Sao Paulo 2018-11-04 gap, Havana fall-back ambiguity); require pinned examples. Validators doing `value in frozenset` on settings/form values raise TypeError for lists.
- Limit services reading a settings blob: "invalid stored value -> default" silently fails open (no limit), and a later read-modify-write save drops the other entries; this branch is usually untested. Also check one error type isn't reused for a different refusal (tier cap -> "Monthly limit reached") and that `skip_*` bypass flags are tied to the one caller they're for.
- Combined timeouts (`_earliest(call, run_timeout)`): a `min`->`max` mutant survives unless a test sets both with each one shorter; and "type timeout > provider run timeout" floors must add the bounded close (DISCONNECT_TIMEOUT 25 s), which runs after the deadline.
